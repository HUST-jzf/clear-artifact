## 3. Findings

**A fixed key works only for an exact resend.** `fixed/dedup_versioned` has one
effect in both `exact` cells and two in both `paraphrase` cells (false split
10/10). When the model re-renders the same intent, the key changes.

**Rebuilding the key on every attempt is a duplicate.** `fresh/dedup_fresh` has
two effects under both faults (duplicate 10/10). This is the direct consequence
of generating a new token per attempt, not an implementation error.

**Content dedup merges different intents.** `semantic_dedup` produces one effect
and reports completion in the same-args-new-intent cell in all three regimes
(false merge 10/10). Same arguments, different intent: a content hash cannot
tell them apart.

**Key-based policies have no free lunch.** The fixed key splits on paraphrase,
the content key merges on same-args-new-intent, and a rebuilt key duplicates.
No key-based policy avoids both errors on A and B.

**`op`-keyed mechanisms make neither error, but `op` is developer-fixed.**
`clear_fenced` has one effect in all four A cells and two under B;
`verify_retry` duplicates only under late commit, independent of identity;
`clear_evidence` has one effect in all A cells and pauses under B. Their
correctness comes from a stable `op` handle, which is exactly what an agent
environment rebuilds. This is the boundary of R46 and the subject of R47.

**CLEAR pauses when the intent cannot be verified.** `clear_evidence` reads a
receipt whose intent differs under `paraphrase` + lost return and pauses 10/10
with one effect; it also pauses 10/10 under B instead of merging `hold` into
`seat`. Under `exact` it completes with one effect in both fault cells.

**One cell needs an explanation.** `clear_evidence` completes with one effect
under `paraphrase` + late commit: when the delayed request enters admission, the
retry has already written the receipt, so admission returns the existing receipt.
The effect count is correct, but the recorded intent text is the new wording.
This is intent-metadata ambiguity, not a duplicated effect; R47 addresses it at
the task level with an intent epoch.

**Cost.** Mean requests per cell: `semantic_dedup` 2.0, `clear_evidence` and
`verify_retry` 2.4, `dedup_versioned`/`dedup_fresh` 4.0, `clear_fenced` 5.2.
Stronger identity costs more requests; fence settlement is the most expensive.

## 4. Optional LLM paraphrase subset

`runs/R46/llm1`: 20 paraphrases generated by `deepseek-flash` at temperature
0.9, each run through a fixed key and through CLEAR under a lost return
(40 workflows). Verification: 5/5 checks, zero SQLite mismatches.

- Every generated paraphrase was `assign seat 12A`; the short prompt converged
  to one wording, so this subset does not add lexical variety.
- `dedup_versioned`: two effects in 20/20 runs (false split 20/20).
- `clear_evidence`: one effect in 20/20 runs, pause 20/20 on the intent mismatch.

The subset confirms the direction of the scripted result: any wording difference
breaks the fixed key, and CLEAR refuses to treat the receipt as the same intent.
It remains external validity and does not enter the main table.
